Rebind

On the ⌘ layer

⌘K ⌘Z ⌘I ⌘[ ⌘] ⌘\ ⌘A ⌘, ⌘/ ⌘0 hollow = bound, not live

Why

Every other direction answers "what does this command do". None of them answers the question you actually have when you are rebinding: is this key free? Today you find out by recording a key and being refused — the conflict check fires after the attempt. A board shows the answer before you press anything, and nineteen bindings on a hundred keys is a picture with a lot of white in it, which is itself honest information about how sparse this app's keyboard really is.

Tradeoff

It is by far the most work, and it does not scale: at forty bindings the board is unreadable and you have built a thing you must then throw away. It is also wrong for the bindings that matter most — ⌘=, ⌘- and ⌘0 sit on a number row nobody looks at, and the layer switch means the twelve ⌘ bindings are never on screen with the five plain ones. ? and / are one physical key with two jobs, which the metaphor has to apologise for. And on an iPad there is no keyboard to draw.

The dead key

The best reading of the three: a hollow key is visibly holding a binding while doing nothing, and it stays in the same place on the board, so a switched-off extension reads as a gap in your own map rather than a row that vanished.

Buildable, but earn it. Worth drawing so it can be argued with — and worth stealing one idea from even if it loses: show what is free, not only what is taken.
