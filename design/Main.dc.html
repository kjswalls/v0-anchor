Finding 2 · the weight is empty scaffolding
Subtasks renders its label and an add-row at zero subtasks. Agent renders "Assign to Beacon" always. Thread renders a label and a composer always. Only Activity and the heatmap are quiet-when-empty. On a brand-new task that is three headings and four controls holding nothing — taller than the chip row above it.
Finding 3 · the registry drives fields, not layout
Every chip asks the registry a capability question — the house rule is honoured, per control. But nothing asks about order, grouping or emphasis. The registry says what a type can do; nothing says what it usually does, so every live capability renders at equal weight, in source order, forever. container-registry.ts already declares three roles — classify, gate, aspire — and the chip row expresses none of them: Project (classify) sits beside Routine (gate) sits beside Goal (aspire) with nothing between.

The question in the ticket title
In the code the sidebar and the page are already one component — item-surface-growth.md made growth a presentation, not a fork, and the split is only at the wrapper. What the user meets is still four surfaces: capture modal, docked panel, mobile drawer, page. The page is the only one that is a genuinely different job — two columns, deep-linkable so Beacon can answer with a URL — and it is also the one that most obviously duplicates the panel, because it renders the properties read-only and then floats the editable copy over them.
So the honest answer is neither "merge" nor "keep two". It is: the panel and the page should stop being two renderings of the same properties. Every direction below has to say how.
